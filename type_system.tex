\section{Notations and Terminology}

\subparagraph{Judgements and terms} To describe the type system, its types and
the inference rules, this document uses "judgements" on "terms".\\*
For example, $t:T$ is a judgement telling that $t$ is a term of type $T$.

\subparagraph{Assumptions} Zero or more assumptions (comma separated) can be
used for a judgement; they're specified before the "turnstile" symbol
$\then$.\\*
For example, $\Env \then t:T$ can be read as "if $\Env$ is true, then $t$
is a term of type $T$".

\subparagraph{Premise} Judgements can be made based on zero or more premises
(space separated judgements).\\*
For example, $\infrule{\Env\then t_1:T \quad \Delta\then
t_2:T}{\Env,\Delta\then \code{$t_1$ + $t_2$}: T}$ means that with a premise
that both judgements $\Env\then t_1:T$ and $\Delta\then t_2:T$ are true,
then $\Env,\Delta\then \code{$t_1$ + $t_2$}: T$ is true.

\subparagraph{Code} Text written with \code{monospaced} font denotes the text
as written in code verbatim. Some types may also be written with
\texttt{Monospace} font (usually in PascalCase).

If the code evaluates to some value, to denote its type the
$:\texttt{SomeType}$ notation will be used.\\*
For example: $\code{59 + 10} : \Int$

To denote to what the value evaluates to, the $\equiv$ symbol will be used.\\*
For example: $\code{59 + 10} \equiv 69$

\subparagraph{Functions} Functions are denoted by a list of zero or more input
arguments followed by an output argument.\\*
For example, $(\tau_1, \tau_2) \to \rho$ describes a function that takes two
arguments of type $\tau_1$ and $\tau_2$ respectively, and produces a value of
type $\rho$

\subparagraph{"Generic" types} Some types are "generic" (a.k.a. existential
types), meaning that they declare one or more type variable (a.k.a. type
parameters).\\*
The notation $T[\tau:=\sigma]$ describes a generic type $T$ with a type
parameter $\tau$ of some type $\sigma$.\\*
The notation $t : \exists\sigma.T$ means that the $t$ is a term of concrete
type $T$ with the type parameter $\tau$ equal to $\sigma$

\paragraph{Product types}

\subparagraph{Tuple} A tuple is denoted with the cartesian product operator.\\*
For example, $\tau \times \sigma \times \rho$ describes a product 3-tuple with
three members of type $\tau, \sigma, \rho$.

\subparagraph{Record} The notation $\tuple{a:\tau, b:\sigma}$ describes a
record (a tuple whose members are named)

\subparagraph{Struct} The notation $(\xi, \tuple{a_1:\tau_1, a_2:\tau_2})$
describes a struct (a pair of an identifier $\xi$ and a record)

\begin{definition}[Types widening/narrowing]
	A type $N$ is said to be "narrower" than a type $W$ iff a value described
	by $N$ can also be described by $W$ without any loss of information.\\*
	Conversely, a type $W$ is said to be "wider" than a type $N$ iff it can
	describe any value described by $N$ without loss of information.\\*
	A "narrower than" relationship is denoted using the $\narr$ operator 
\end{definition}

The $\sqcap$ operator produces the least wide type for the operand types
\[
	\infrule[aligned]{
		\Env & \then \tau_1:\Type \quad \tau_2:\Type \\*
		\Env & \then \exists_{\omega:\Type}{\tau_1\narr\omega \land \tau_2\narr\omega} \\*
		\Env & \then \nexists_{\sigma:\Type}{\tau_1\narr\sigma \land \tau_2\narr\sigma \land \sigma\narr\omega}
	}{
		\Env\then \tau_1 \sqcap \tau_2 = \omega
	}
\]

\subsection{Type environments}

The definition of an expression type is done within a "context" (a.k.a. type
environment) which describes the type of any identifier or any other
expressions appearing in the described expression.

The general type environment is denoted by $\Env$, a function that maps an
identifier to its type.

To avoid ambiguities and to more clearly describe expressions, $\Env$ is
partioned in the $\EnvVar,\EnvConst,\EnvFunc,\EnvStucts$ environments:

\begin{itemize}
	\item $\EnvVar$: the Variable environment, a function that maps a variable
		identifier $i$ to its type $\tau$
		\[
			\begin{split}
				\EnvVar : \Id &\to \Type\\*
				\EnvVar(i)    &\mapsto \tau
			\end{split}
		\]
	\item $\EnvConst$: the Constants environment, a function that maps a
		constant identifier $i$ to its type $\tau$
		\[
			\begin{split}
				\EnvConst : \Id &\to \Type\\*
				\EnvConst(i)    &\mapsto \tau
			\end{split}
		\]
	\item $\EnvFunc$: the Functions environment, a function that maps a
		function identifier $i$ to its definition signature $(i, \phi)$
		\[
			\begin{split}
				\EnvFunc : \Id &\to (\Id, \Function)\\*
				\EnvFunc(i)    &\mapsto (i, \phi)
			\end{split}
		\]
		With a type $\tau$, it maps to the function defined within the type
		$\tau$
		\[
			\begin{split}
				\EnvFunc : (\Type,\Id) &\to (\Id, \Function)\\*
				\EnvFunc(\tau, i)      &\mapsto (i, \phi)
			\end{split}
		\]
	\item $\EnvStucts$: the Structs environment
		\[
			\begin{split}
				\EnvStucts : \Id &\to (\Id, \Record)\\*
				\EnvStucts(i)    &\mapsto (i, \rho)
			\end{split}
		\]
		A function that maps a typename $i$ (struct definition identifier) to
		its type definition (identifier $i$ and record $\rho$)
	% \item $\EnvModules$: the Modules environment
	% 	\[
	% 		\begin{split}
	% 			\EnvModules : \Id & \to \Module\\*
	% 			\EnvModules(i)    & \mapsto m
	% 		\end{split}
	% 	\]
	% 	A function that maps an identifier $i$ to the module
\end{itemize}

The $\Env$ function can now be defined as follows
\[
	\begin{split}
		\Env : \Id & \to \Type\\*
		\Env(i) & \mapsto \begin{cases}
			\EnvStucts(i) &\text{ if } \EnvVar(i)=\varnothing \land \EnvConst(i)=\varnothing \land \EnvFunc(i)=\varnothing \\*
			\EnvFunc(i) &\text{ if } \EnvVar(i)=\varnothing \land \EnvConst(i)=\varnothing \\*
			\EnvConst(i) &\text{ if } \EnvVar(i)=\varnothing \\*
			\EnvVar(i) & \\*
			% \EnvModules(i) & \text{ if } \\*
		\end{cases}
	\end{split}
\]
which formally describes the lookup order and priority of a generic symbol $i$

\paragraph{Environment extension} Given how scopes and symbols lookup work, it
will be useful to define "new" type environments extending an existing
environment. The notation $E\env{t:\tau}$ will be used to denote that the
environment $E$ is extended with $\env{t:\tau}$.

Using the $\EnvVar$ variables environment as example
\[
	\EnvVar\env{t:\tau}(u) \mapsto \begin{cases}
		T &\text{ if } u = t \\*
		\EnvVar(u) & \\*
	\end{cases}
\]

\paragraph{Tuple}

\[
	\infrule{
		\Env\then n \geq 0 \quad \forall_{i\in[1,n]}{\tau_i:\Type} \quad \theta_1 = \bigtimes_{i \in [1,n]}{\tau_i}\\*
		\Env\then m \geq n \quad \forall_{i\in[1,m]}{\omega_i:\Type} \quad \theta_2 = \bigtimes_{j \in [1,m]}{\omega_j}\\*
		\Env\then \forall_{i \in [1,n]}{\tau_i \narr \omega_i}
	}{
		\Env\then \theta_1 \narr \theta_2
	}
\]
A tuple type $\theta_1$ is narrower than the tuple type $\theta_2$ if the first
$n$ fields of $\theta_1$ have a type $\tau$ narrower than the first $n$ fields
types $\omega$ of $\theta_2$

\[
	\infrule{
		\Env\then n \geq 0 \quad \forall_{i\in[1,n]}{\tau_i:\Type} \quad \theta = \bigtimes_{i \in [1,n]}{\tau_i}\\*
		\Env\then m \geq n \quad \forall_{j\in[1,m]}{\eta_j \in \Id, \omega_j:\Type} \quad \rho = \tuple{\eta_1:\omega_1,...,\eta_m:\omega_m} \\*

		\Env\then \theta \narr \rho
	}

A tuple type $\theta$ is narrower than the record type $\rho$ if the first $n$

\paragraph{Record}

\[
	\infrule{
		\Env\then n \geq 0 \quad \forall_{i\in[1,n]}{a_i \in \mathcal{N} \subseteq \mathcal{M}, \tau_i:\Type} \quad \rho_1 = \tuple{a_1:\tau_1,...,a_n:\tau_n} \\*

		\Env\then \forall_{a':\tau'\in\mathcal{N}}{\exists_{b':\omega'\in\mathcal{M}}{a'=b' \land \tau' \narr \omega'}}
	}{
		\Env\then \rho_1 \narr \rho_2
	}
\]
A record type $\rho_1$ is narrower than a record type $\rho_2$ if, for all
fields $a'$ of type $\tau'$ in $\rho_1$, there is a field with the same name
$b'$ of type $\omega'$ in $\rho_2$, where $\tau'$ is narrower than $\omega'$

		\Env\then \forall_{a':\tau'\in\mathcal{N}}{\exists_{b':\omega'\in\mathcal{M}}{a'=b' \land \tau' \narr \omega'}}

		\Env\then \rho \narr \sigma
	}
\]
A record type $\rho$ is narrower than a struct type $\sigma$ if, for all fields
$a'$ of type $\tau'$ in $\rho$, there is a field with the same name $b'$ of
type $\omega'$ in $\sigma$, where $\tau'$ is narrower than $\omega'$ (struct
name is ignored)

A struct type $\sigma_1$ is narrower than a struct type $\sigma_2$ if and only
if they have the same name (fields are ignored since they're equal by
construction).

A function type $\phi_1$ is narrower than a function type $\phi_2$ if the
return type $\rho_1$ is narrower than the other return type $\rho_2$, and if,
for all parameters $a'$ of type $\tau'$ in $\phi_1$, there is a parameter with
the same name $b'$ of type $\omega'$ in $\phi_2$, where $\tau'$ is narrower
than $\omega'$.

\chapter{Operational semantics}

This section provides a semi-formal definition of the operational semantics of
the language, definining the state and context and how they mutate with every
expression.

\section{Notation and terminology}

\paragraph{Common sets} Some sets will be used throughout the rules
\[
	\begin{split}
		\Expr &= \set{\expr \mid \expr := \text{any expression}} \\*
		\Val  &= \set{\val \mid \val := \text{any value}} \\*
	\end{split}
\]

\subparagraph{Expression} The $\expr$ will be used to denote any expression
permitted by the language (e.g. a literal, a binary expression, a function
invocation etc.).\\*
Unless noted otherwise, $\expr \in \Expr$ is implied.

\subparagraph{Expression's value} To denote to what value an expression evaluates
to, the $\equiv$ symbol will be used, for example: $\expr \equiv \val$\\*
To specify the value along with its type, the notation $\tau(\val)$ will be
used, where $\tau:\Type$ and $\val\in\Val$, for example: $\expr:\Int(\val)$\\*
Unless noted otherwise, $\val \in \Val$ is implied.

\paragraph{Environments} Two environments will be used:
\begin{itemize}
	\item $\EnvLoc :=$ \textbf{location environment}. Describes the
		mappings/bindings between identifiers and their "location/address" in
		memory.
		\[
			\begin{split}
				\EnvLoc: \Id & \to \mathbb{Z}\\*
				\EnvLoc(i) & \mapsto a
			\end{split}
		\]
		Occasionally, the function will be applied on an expression
		\[
			\begin{split}
				\EnvLoc: \Expr & \to \mathbb{Z}\\*
				\EnvLoc(\expr) & \mapsto a
			\end{split}
		\]
	\item $\EnvStore :=$ \textbf{store environment}. Describes the mappings
		between a location in memory and its data content
		\[
			\begin{split}
				\EnvStore : \mathbb{Z} & \to \Val \\*
				\EnvStore(a) & \mapsto \val
			\end{split}
		\]
\end{itemize}

\nb{
	"Location" and "memory" are used loosely here. They do not represent an
	actual computer memory, but rather an abstraction of it.
}

\paragraph{Expression's location} The expression location and its value
mappings in the environment is implied
\[
	\expr\equiv\val
	\implies \exists_\addr{\EnvLoc(\expr)=\addr \land \EnvStore(\addr)=\val}
\]

\paragraph{Values identity} In this context, values do not have an identity,
meaning that if two memory locations are mapped to the same value, the value
data is effectively duplicated.

\paragraph{Unmapped values} A slight abuse of notation is used to denote the
lack of mapping in an environment via the $\varnothing$ symbol.\\*
For example: $\EnvLoc(i) = \varnothing, \EnvStore(a) = \varnothing$

\paragraph{Environment extension} To denote a environment extending, modifying
or overriding an existing one, this notation will be used $\EnvLoc\env{i \mapsto
a}$ where it's defined as follows:
\[
	\EnvLoc\env{i \mapsto a}(j) \mapsto \begin{cases}
		a          &\text{ if } i = j\\
		\EnvLoc(j) &\text{ if } i \neq j\\
	\end{cases}
\]

Multiple mappings may be specified: $\EnvLoc\env{i_1 \mapsto a_1, i_2 \mapsto a_2}$

\subparagraph{The $\alloc()$ function} When store environment is extended with
a mapping, it's implicit that it is added if it does not exist, and it is
updated if it already exists. In some cases, to improve clarity, the $\alloc()$
function will be used to explicitly state that a new memory "address" is
allocated in the specified environment. The $\alloc()$ function takes a store
environment and returns the newly allocated address.\\*
For example: $a = \alloc(\EnvStore)$

% \subparagraph{The $\copi()$ function} The language (almost) never pass values
% by reference, hence many copies are made during an execution. The simplify the
% rules, a $\copi()$ function is used as a shorthand for allocating a new address
% and mapping it a copy of the specified value

\paragraph{Environment modification} If the evaluation of an expression
results in an alteration of an environment, the judgment may be followed by a
"double turnstile" symbol $\Then$ and the new environments.\\*
For example: $\EnvLoc,\EnvStore \then \expr \Then \EnvStore_2$

\subsection{Zero values}

The concept of a "default" value (a.k.a. zero value) is very important since
the language has no concept of (nor models) a "null" value or uninitialized
memory.

Every variable, constant, function parameter, product types member etc. gets
automatically initialized to its type's zero value.

Every type has a zero value and will be described using $\Zero$
\[
	\begin{split}
		\Zero : \Type &\to \Val \\*
		\Zero(\tau)   &\mapsto \val
	\end{split}
\]

In some cases the zero value may be overridden. In that case the $\Zero$
function can be applied on an identifier
\[
	\begin{split}
		\Zero : \Id &\to \Val \\*
		\Zero(i) &\mapsto \begin{cases}
			\val             &\text{ if default overridden } \\*
			\Zero(\Env(i)) &
		\end{cases}
	\end{split}
\]

\subsubsection{Primitive types}

\[
	\begin{split}
		\Env\then \Zero(\Bool)    &= \Bool(\texttt{false}) \\*
		\Env\then \Zero(\Text)    &= \Text(\texttt{""}) \\*
		\Env\then \Zero(\Natural) &= \Natural(\texttt{0}) \\*
		\Env\then \Zero(\Int)     &= \Int(\texttt{0}) \\*
		\Env\then \Zero(\Real)    &= \Real(\texttt{0}) \\*
		\Env\then \Zero(\Type)    &= \Type(\Void) \\*
		\Env\then \Zero(\Void)    &= \Void() \\*
	\end{split}
\]

		\Env,\EnvLoc,\EnvStore \then \code{$i$ $\tau$}
		\Then \EnvLoc\env{i \mapsto \addr},\EnvStore\env{\addr \mapsto \Zero(\tau)}
	}
\]

\subparagraph{Initialization} A variable can be initialized at declaration
\[
	\oprule[aligned]{
		\Env                  &\then i \in \Id \quad \tau : \Type \\*
		\EnvLoc,\EnvStore     &\then \EnvLoc(i) = \varnothing \\*
		\EnvLoc,\EnvStore     &\then \expr \equiv \val \Then \EnvLoc_2,\EnvStore_2 \\*
		\EnvLoc_2,\EnvStore_2 &\then \addr = \alloc(\EnvStore_2) \\*
	}{
		\EnvLoc_2,\EnvStore_2 \then \code{$i$ $\tau$ default $\expr$}
		\Then \EnvLoc_2\env{i \mapsto \addr},\EnvStore_2\env{\addr \mapsto \val}
	}
\]


\subparagraph{Zero override} At (and only at) declaration, the zero value of a
variable can be overridden
\[
	\oprule[aligned]{
		\Env                  &\then i \in \Id \quad \tau : \Type \\*
		\EnvLoc,\EnvStore     &\then \EnvLoc(i) = \varnothing \\*
		\EnvLoc,\EnvStore     &\then \expr \equiv \val \Then \EnvLoc_2,\EnvStore_2 \\*
		\EnvLoc_2,\EnvStore_2 &\then \addr = \alloc(\EnvStore_2) \\*
	}{
		\EnvLoc_2,\EnvStore_2 \then \code{$i$ $\tau$ default $\expr$}
		\Then \EnvLoc_2\env{i \mapsto \addr},\EnvStore\env{\addr \mapsto \val}
	}
\]

\subparagraph{Initialization vs Zero override} Initialization and zero
override may seem identical, but they do two different things:
\begin{itemize}
	\item initialization: initializes the variable values with the one provided
		(without overriding its zero value, which remains equal to its type's
		zero value)
	\item zero override: overrides the variable's zero value (to which the
		variable is initialized to)
\end{itemize}
Both can be performed in a single statement
\[
	\oprule[aligned]{
		\Env                  &\then i \in \Id \quad \tau : \Type \\*
		\EnvLoc,\EnvStore     &\then \EnvLoc(i) = \varnothing \\*
		\EnvLoc,\EnvStore     &\then \expr_z \equiv \val_z \Then \EnvLoc_2,\EnvStore_2 \\*
		\EnvLoc_2,\EnvStore_2 &\then \expr \equiv \val \Then \EnvLoc_3,\EnvStore_3 \\*
		\EnvLoc_3,\EnvStore_3 &\then \addr_z = \alloc(\EnvStore_3) \\*
		\EnvLoc_3,\EnvStore_3 &\then \addr = \alloc(\EnvStore_3) \\*
	}{
		\EnvLoc_3,\EnvStore_3 \then \code{$i$ $\tau$ default $\expr_z$ <- $\expr$}
		\Then \EnvLoc_3\env{i \mapsto \addr},\EnvStore\env{\addr \mapsto \val,\addr_z \mapsto \val_z} \\*
		\hfill\implies \code{$i$} \equiv \val \land \Zero(i) = \val_z
	}
\]
